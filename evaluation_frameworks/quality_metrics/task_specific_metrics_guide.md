# Task-Specific Quality Metrics\n\nWhile generic metrics like accuracy and perplexity provide some insight, evaluating LLMs often requires metrics tailored to the specific downstream task they are performing. Here are some common task-specific metrics:\n\n## 1. Question Answering (QA)\n\n*   **Exact Match (EM):** Measures the percentage of predictions that match the ground truth answer *exactly*. It's a strict metric.\n*   **F1 Score:** Treats prediction and ground truth as bags of words and computes the harmonic mean of precision and recall at the word level. It's more lenient than EM and accounts for partial overlaps.\n\n## 2. Text Generation (Summarization, Translation, etc.)\n\nThese metrics typically compare the model-generated text to one or more human-written reference texts.\n\n*   **BLEU (Bilingual Evaluation Understudy):** Measures n-gram precision overlap between the generated text and references, adding a brevity penalty for generations that are too short. Widely used, especially for machine translation, but known to correlate poorly with human judgment for fluency and adequacy.\n*   **ROUGE (Recall-Oriented Understudy for Gisting Evaluation):** Measures n-gram recall overlap. Several variants exist:\n    *   `ROUGE-N`: Measures recall of N-grams (e.g., ROUGE-1 for unigrams, ROUGE-2 for bigrams).\n    *   `ROUGE-L`: Measures recall based on the Longest Common Subsequence (LCS).\n    Commonly used for summarization.\n*   **METEOR (Metric for Evaluation of Translation with Explicit ORdering):** Considers synonymy (using WordNet) and stemming, along with precision and recall of unigrams. Generally correlates better with human judgment for translation than BLEU.\n*   **BERTScore:** Computes semantic similarity between tokens in the generated text and reference text using contextual embeddings (like BERT). Correlates better with human judgment than n-gram based metrics.\n*   **BLEURT:** A learned metric trained on human ratings to predict the quality of generated text. Often shows strong correlation with human evaluation.\n\n## 3. Code Generation\n\n*   **Pass@k:** Measures the functional correctness of generated code. The model generates \(k\) code samples for a given problem description. If *at least one* of these samples passes a predefined set of unit tests, the problem is considered solved. The Pass@k score is the percentage of problems solved under these conditions. `Pass@1` is a common specific case.\n*   **CodeBLEU:** An adaptation of BLEU for code, considering syntactic structure (Abstract Syntax Trees) and data flow in addition to n-gram overlap.\n\n## 4. Classification Tasks (Sentiment, Intent, etc.)\n\n*   **Accuracy:** Standard metric for overall correctness.\n*   **Precision, Recall, F1 Score:** Useful especially when dealing with imbalanced classes or when false positives/negatives have different costs. Often reported per-class and macro/micro/weighted averages.\n*   **AUC (Area Under the ROC Curve):** Measures the model's ability to distinguish between classes across different thresholds.\n\n## Implementation Notes\n\nCalculating many of these metrics (especially for text generation) involves complex logic. Libraries are highly recommended:\n\n*   **Hugging Face `evaluate`:** A comprehensive library providing implementations for dozens of metrics (including BLEU, ROUGE, METEOR, BERTScore, accuracy, F1, etc.) with a unified API. Integrates well with Hugging Face `datasets`. ([https://huggingface.co/docs/evaluate](https://huggingface.co/docs/evaluate))\n*   **NLTK:** Includes implementations for metrics like BLEU.\n*   **Scikit-learn:** Provides implementations for standard classification metrics (accuracy, precision, recall, F1, AUC).\n\nChoosing the right metric depends heavily on the specific task and what aspect of performance (fluency, accuracy, correctness, similarity) you want to measure.
